# Product Experience Research — 2026 Redesign

## Evidence reviewed

Todoist’s public product narrative centers the immediate capture action, then narrows the working set through Today, Upcoming, and filters rather than presenting every organizing mechanism at once.[1] Sunsama frames the day as a guided sequence: select work, make time estimates, keep the day realistic, and place the chosen work into time.[2]

| Source pattern | Product implication for Personal Calander |
| --- | --- |
| Capture before classification | Keep one always-recognizable capture entry point, then reveal detail only when it helps the next decision. |
| A deliberately narrowed working set | Make the current commitment and time canvas the visual center; move support systems behind intentional reveal patterns. |
| Capacity is a planning constraint, not an analytics afterthought | Give today’s available attention a compact, legible physical artifact tied to planned work. |
| Goals and habits gain meaning through today’s choices | Surface directional context as a quiet companion to the current plan, not as equal-weight dashboard furniture. |

## Redesign hypothesis

The new experience should read less like a collection of administrative panels and more like a **personal planning studio**: a command surface for deciding what matters now, a time field that makes the trade-off visible, and a small set of tactile planning artifacts that connect daily work to longer horizons. This will retain the proven distinction between task time, habit rhythm, goals, review, and optional device utilities while replacing the current repeated-card composition.

## Comparative workflow findings

Things explicitly separates capture from commitment: its Inbox accepts unclassified work, while Today is a deliberate list of work to start before the day ends; Upcoming and Someday keep future and optional work from overwhelming the active view.[3] It also positions projects as multi-step outcomes and areas as ongoing life domains, which reinforces the distinction between a one-off commitment and a durable direction.[3]

TickTick demonstrates the opposite risk and opportunity for a rich product: its public product surface spans task lists, several calendar views, habits, focus timing, matrices, notes, reminders, filters, and statistics.[4] Its feature inventory makes clear that a capable planner benefits from strong top-level mode separation and intentional view selection, rather than trying to show every available capability in one workspace.[4]

| Comparative lesson | Personal Calander design decision |
| --- | --- |
| Capture should not demand early classification | Preserve instant task capture, but move its supporting options into a deliberately staged composer rather than surrounding the capture field with equal-weight controls. |
| Today must be a committed working set | Rebuild Today around a clear focus cue and attention ledger; archive, review, category, AI, and device details become contextual layers. |
| Planning horizons need separate but connected modes | Keep the existing dedicated Tasks, Calendar, Goals, Habits, and Review routes; add visual links between them rather than collapsing their meanings. |
| Rich systems need opinionated visual hierarchy | Use one strong navigation system, one primary decision surface per route, and context-appropriate secondary artifacts instead of a uniform dashboard. |

## Goal, habit, and time-field findings

Strides’ public model distinguishes habit logging, target tracking, rolling averages, and project milestones rather than forcing every form of progress into one score.[5] Its Daily Goals view narrows attention to trackers that need a log now, while reporting remains a separate progress-reading context.[5] This supports keeping Personal Calander’s dedicated habit tracker and goal runway distinct, with concise cross-links from Today instead of an undifferentiated combined dashboard.

The Time-Block Planner’s method makes capacity tangible through a preliminary day grid and a separate capture collection area: work can be captured without interrupting the active time block, and the plan can be adjusted after disruption.[6] This reinforces Personal Calander’s existing separation between quick capture and time planning, and motivates a more legible attention ledger beside the time canvas.

| Research finding | Implementation implication |
| --- | --- |
| Different progress types deserve different visual grammars | Goals use runway and pace; habits use rhythm and check-ins; tasks use commitment and state; time blocks use spatial duration. |
| Daily attention should narrow to items that need a decision now | Today will foreground focus and capacity, while deeper analytics remain a later read rather than initial competing content. |
| Capture must not break the current planning act | The quick-capture affordance remains persistent but visually subordinate to the active route’s primary decision field. |
| A plan is revised after interruption, not treated as a scorecard | Reschedule and undo controls must remain directly discoverable and keep recovery language calm and specific. |

## Research boundary

The cited products are used as evidence for patterns, not as visual templates. Personal Calander will retain its own verified model—especially task-only Calendar semantics, dedicated habit history, confirmation-first AI drafting, private iCalendar, offline capture, and paused automatic reminders—while adopting only the interaction principles that improve clarity, recovery, and focus.
