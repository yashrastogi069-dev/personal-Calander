# Testing Strategy

## Business rules

Unit tests will cover lifecycle transitions, dependency cycle rejection, horizon validation, optimistic update rollback, conflict detection, recurrence generation, skipped/missed/completed outcomes, habit streak math, timezone date conversion, calendar rescheduling, and dashboard aggregates.

## Interface verification

The UI will be verified in desktop and mobile viewports. Critical paths include rapid capture, full task editing, completion, bulk update, saved-view recall, recurrence modifications, habit check-ins, calendar drag-and-drop, review generation, reminder opt-out, AI draft confirmation, and conflict recovery.

## Acceptance standard

No completion path may silently drop a task, mutate historical recurrence data, cross a workspace boundary, or change a local planning date because of a timezone conversion. New core features require tests before delivery and must display loading, empty, success, and error behavior where applicable.

## Current verification evidence

The automated suite verifies task-backed goal progress, progress clamping, inclusive local-date sequences including a month boundary, skipped and missed habit behavior, and over-capacity workload detection. Browser checks verified anonymous workspace bootstrap, real quick capture, immediate dashboard refresh, task completion/reopening, and confirmation-based goal creation. The next integration phase will add connector-specific tests before external calendars or phone notification channels are enabled.

## Offline capture and Today reschedule validation

Quick capture now has a bounded offline-first path. A previously opened planner shell is cached by the service worker; API requests are deliberately excluded from that cache. When the browser is offline, a task title, workspace, timezone, local planned date, timestamp, and client-generated capture ID are stored locally. On the next online event or planner open, the client replays that exact capture through the normal task-create contract. The database now enforces a unique `(workspaceId, clientRequestId)` pair, and the persistence service returns the previously created task if a response was lost and the same capture is replayed. This prevents the normal ambiguous-network-retry duplicate class rather than merely hiding duplicate rows in the UI.

The focused queue tests prove workspace isolation, one queue record per capture ID, removal after successful replay, corrupt-storage fail-closed behavior, and network-only retry classification. Router coverage proves that `clientRequestId` is accepted by task creation and that the nearby-day move remains a version-safe `scheduledLocalDate` update. The full suite passes with **54 tests across 13 files**; `pnpm check` and `pnpm build:client` also pass. The build retains the existing non-fatal large-chunk warning.

The Today list accepts a horizontal swipe—or its visible previous/next-day controls—to move only the task’s planned date by one local calendar day. The gesture is deliberately limited to Today, leaves due dates and reminder cadence unchanged, and reports its success or error in the panel. A local browser proof injected one synthetic queue entry only into isolated browser storage, verified the persistent pending-copy render, and removed the fixture before it could replay. Desktop and 390×844 phone renders remained stable, and the interface detector reported no findings for the changed planner files.
